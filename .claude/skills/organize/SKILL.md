# 풀이 정리

사용자는 레포 루트에 **규칙대로 이름을 붙인 풀이 파일**을 만들어 둔다 (예: `PG_LV1_기사단원의무기.md`). 파일 안에는 문제 링크와 풀이 코드가 있다. 이 파일들을 찾아서 유형을 분류하고, 알맞은 폴더로 옮기고, 핵심 아이디어를 채운다. 중간에 확인받지 않고 끝까지 진행한 뒤 결과를 요약해서 보여준다.

## 기준이 되는 파일 (매번 새로 읽는다)

- `README.md`의 `## 분류 기준` 섹션: 헷갈릴 때 규칙
- `scripts/generate-readme.mjs`의 `CATEGORIES`: 폴더 목록과 각 유형의 정의 ("이럴 때 여기")
- `TEMPLATE.md`: 풀이 파일 양식

여기에 없는 기준을 지어내지 않는다.

## 순서

### 1. 정리할 파일 찾기

1. `git pull`로 원격의 변경을 먼저 받는다. GitHub 웹에서 풀이를 올렸을 수도 있기 때문이다.
2. 루트에 있는 `.md` 파일 중 `README.md`, `TEMPLATE.md`, `CLAUDE.md`를 뺀 나머지가 정리 대상이다.
3. 대상이 없으면 "루트에 정리할 풀이 파일이 없어요"라고 말하고 끝낸다.

파일마다 아래 2~5단계를 진행한다.

### 2. 파일 이름 확인

- 파일 이름은 사용자가 정한 것이다. **바꾸지 않는다.**
- 이름이 `사이트_난이도_문제이름.md` 형식인지만 확인한다.
  - 사이트: `BOJ`, `PG`, `CT`
  - 난이도: 백준·코드트리는 `B5`~`R1` 티어(예: `G4`), 프로그래머스는 `LV0`~`LV5` 또는 `PCCP`
- 형식에 맞지 않으면 **건드리지 않고 루트에 남겨 두고**, 요약에서 무엇이 틀렸는지 알려준다.

### 3. 이미 푼 문제인지 확인

레포 전체에서 같은 문제 링크를 찾는다. 이미 있으면 새 파일을 만들지 않는다. 대신 기존 파일의 마지막 `# Pass N` / `# Fail N` 다음 번호로 이번 코드를 이어 붙이고, 루트의 파일은 지운다.

### 4. 분류하기

- 기준은 문제의 공식 태그가 아니라 **사용자가 실제로 쓴 코드의 핵심 기법**이다. 코드를 읽고 판단한다.
- `분류 기준`의 규칙을 순서대로 적용한다. 여러 기법이 섞였으면 "이게 없으면 못 푸는" 쪽으로 정한다.
- 같은 폴더에서 구조가 비슷한 풀이를 1~2개 찾아 근거로 삼는다.
- 어느 유형에도 맞지 않으면 억지로 넣지 말고 루트에 남겨 둔 채, 요약에서 `CATEGORIES`에 새 유형을 추가할지 묻는다.

### 5. 파일 다듬기와 이동

`TEMPLATE.md` 양식에 맞춘다.

- 첫 줄은 문제 링크다.
- **코드는 한 글자도 바꾸지 않는다.** 코드 정리는 사용자의 에디터가 저장할 때 한다.
- 코드 위에 제목이 없으면 `# Pass 1 - JavaScript`를 붙이고, ` ```javascript ` 코드 블록으로 감싼다. 언어가 JavaScript가 아니면 제목과 코드 블록 언어를 맞춘다. 사용자가 이미 `# Fail 1`, `# Pass 1`처럼 써 두었으면 그대로 둔다.
- `# 핵심 아이디어`가 비어 있으면 코드에서 읽히는 핵심을 1~3줄로 쓴다. 어떤 기법을 왜 썼는지가 드러나게 쓴다. 사용자가 이미 써 두었으면 고치지 않는다.
- `# 막혔던 점 / 배운 점`은 사용자가 쓴 내용이 있을 때만 남긴다. 없으면 `- ` 한 줄로 비워 둔다. **지어내지 않는다.**

다듬은 파일을 같은 이름 그대로 `<유형 폴더>/`로 옮긴다. 그 폴더에 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 루트에 남겨 둔 채 요약에서 알린다.

### 6. 커밋하지 않는다

- **커밋도 push도 하지 않는다.** 사용자가 옮겨진 파일을 열어 `막혔던 점 / 배운 점`을 채우거나 핵심 아이디어를 고친 뒤 직접 커밋하도록 변경을 작업 트리에 남겨 둔다.
- README는 건드리지 않는다. push되면 GitHub Actions(`update-readme.yml`)가 갱신한다.
- 요약 끝에 커밋할 때 쓸 메시지를 제안한다. 파일 하나면 `[PG LV1] 기사단원의무기 - 수학`, 여러 개면 `풀이 N개 추가` 제목 아래에 같은 형식으로 한 줄씩 쓴다.
- 사용자가 나중에 "커밋해줘"라고 하면 그때 이 메시지로 커밋하고, push는 따로 물어본 뒤에 한다.

### 7. 요약

파일마다 한 줄씩 보여준다.

```
✅ PG_LV1_기사단원의무기.md → math/
   근거: 약수 개수를 배수마다 세는 정수론 → 수학 (비슷한 풀이: math/PG_LV2_두원사이의정수쌍.md)
⚠️ 공유기설치.md → 남겨 둠: 이름에 사이트와 난이도가 없어요. BOJ_G4_공유기설치.md처럼 바꿔 주세요
```

분류가 애매했던 파일은 다른 후보 유형과, 왜 그쪽이 아닌지를 한 줄 덧붙인다.

마지막에 "`막혔던 점 / 배운 점`을 채운 뒤 커밋하세요"라고 안내하고, 제안 커밋 메시지를 보여준다.
